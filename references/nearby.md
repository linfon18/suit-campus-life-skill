# 校园周边一语查

根据一句自然表达查询学校周边店铺和生活服务，例如“附近咖啡厅”“找个安静能坐着学习的地方”“校门口打印店”“修手机”“周边便宜的聚餐餐厅”。示例不是固定口令。模型提取类别、预算、距离 / 出行方式、目的、时间和排除项；已知条件不再问，直接查询并筛选。没有预算或具体校门也可先查，不发初始化问卷。

## 默认学校位置

默认固定为 **深圳信息职业技术大学，深圳市龙岗区龙翔大道2188号**；旧称“深圳信息职业技术学院”仅作同址检索别名。学校名称 / 地址依据校方站点 `https://www.suit-sz.edu.cn/` 的公开信息，2026年11月14日核对；既有条目可能仍用旧称，需要确认地址一致。

不做 IP 定位、城市中心定位、地理编码，不索要城市、定位权限、API Key 或账号。不能把模型运行环境所在国家 / 城市当成用户位置。用户未说明其他位置就直接带学校名称搜索；明确说“东门 / 我现在在某地”等才采用其地点条件，不擅自声称校门已经核实。外地同名店和深圳职业技术大学等其他学校的结果排除。

本模块不用带 Key 的高德 / 百度 / 腾讯 POI、地理编码或天气接口，不读取配置中的凭证，不从网页提取别人 Key，不把请求示例中的 Key 写进包。没有经纬度也可以用固定校名、地址与真实检索完成咨询；不伪造坐标、半径筛选、全店覆盖、精确距离或导航耗时。

## 环境搜索优先

1. 用环境搜索查询“深圳信息职业技术大学 龙岗 附近 + 类别”，必要时并发用旧称或“龙翔大道2188号 + 类别”补查；2–3条查询通常足够。保留用户需求用于语义筛选，不把“安静”之类主观要求当作已知店铺事实。用户位置已明确，不先做餐饮自检，不查全校菜单。
2. 可直接 GET 下表的公开地图检索入口取得店名、地址与列示时段，缺失属性再读可用的地图店铺页、品牌门店页、商场门店目录等；普通查询优先核实2–3个候选，不为一个咖啡需求爬全城。来源必须能对应这家分店，不能用同品牌另一店的时间、价格或环境。
3. 地址能确定在学校周边才进入推荐。没有坐标 / 路线证据时不按“最近”排序，也不声称几分钟走到；可按已核实的需求匹配程度给候选。仅与龙岗区相关但远近不明的条目不能冒充校门口店铺。无法证明近邻关系时标为“待确认位置的线索”。
4. 营业时间、闭店、预算、评价、插座、Wi-Fi、是否安静、能否久坐各自核实。搜索摘要只能作线索，公开评价是主观反馈；没有当前资料就写“未核实”，不能根据“咖啡厅”推断适合自习。“现在营业”需适用日期、时区和明确营业信息；页面列了常规时段仍不保证当下营业、座位或库存。
5. 每次新的独立查店默认重新检索，不因会话很久仍有旧结果就冒充当前。连续追问改预算、换一家可以利用本轮来源；要求现在营业、路线、价格刷新时重新核对对应信息。网络失败只补失败部分，沿用统一重试规则，不重复已成功的查询。

普通回答给2–3个有来源的候选，满足多少报多少，优先“店名 / 分店、地址、匹配原因、已知价格或营业信息、待核实项”。硬条件不足时明确说“还不能确认符合”，不静默放宽预算、步行范围或忌口。没有可靠候选就给已查范围和具体缺口，不编店名，不仅回复“请自行搜索”。

### 可直接读取的公开地图入口

| 方法 | 地址与参数 | 返回与用途 |
|---|---|---|
| GET | `https://map.baidu.com/?qt=s&c=340&wd=<URL编码的校名和类别>&rn=10` | 百度公开地图检索页；当前可返回 JSON，`content` 为商户列表，`result.total` 为服务声明的总数；`c=340` 为此页面的深圳城市编号 |

并发两条查询：`深圳信息职业技术大学 附近 <类别>`、`深圳信息职业技术学院 <类别>`，URL 编码后替换 `wd`。类别用模型提取的可检索对象，如“咖啡厅”“打印店”；预算、安静、插座等条件留给模型结合证据判断，不把整句要求塞进关键词。匿名 GET，不带 Cookie / Authorization，不需要其他参数。只读每条第一页最多10条，不翻页全城遍历；默认新旧校名两条结果合并去重，不是完整周边商户普查。

按结构提取 `name`、`addr`、`area_name`、`admin_info.city_name / area_name`。`business_time.data[].business_time_text.common / festival` 是平台列示常规 / 节假日时段，`business_time.update_time` 是来源更新时间，不是本次采集时间，更不证明此刻营业。响应中的 `auth`、会话和调试字段、深层 `ext` 小组件不读取、不返回、不用来发后续请求。没有明确金额和评分字段时保持未知。

这是公开网页的读取方式，非承诺稳定的开发者 API。HTML 验证码、结构变化、错误对象或缺少名称地址不能算查询成功；只得到深圳全市泛化结果也不算校门周边。有效空结果保留空，不重试找出“演示店铺”。地址显示在校内可标“校内”；其他学校内部店需注明进入限制未核实，不能冒充本校店或对公众开放。仅街道相邻或地图返回不足以证明精确距离，远近尚不明时列线索。

## 内置 Python 保底

环境没有搜索 / FETCH、公开页面受阻或无法取得可读结果时，自动用本包脚本；不让用户配置 Key、手填 JSON 或自己执行命令，也不通读源码 / 临时搭 PowerShell。将关键词替换为本轮实际对象和可检索条件：

```text
python -I -S -B -X utf8 "<技能目录>/scripts/nearby.py" --query "咖啡厅"
python -I -S -B -X utf8 "<技能目录>/scripts/nearby.py" --query "打印店"
```

脚本以固定学校的新旧名称并发读取上述公开地图入口，按商户身份与地址合并，返回精简字段及实际来源。无 Cookie、登录、Key、配置写入或缓存；仅标准库，复用包内 `official_fetch.py` 的1 MB有界读取和最多首次加两次网络重试，仅失败请求重试。401 / 403、验证码不换身份重试，解析失败直接报告。不能取消平台网络授权，被拒绝时不换身份或工具绕过。公开服务可能缺结果、限流、验证码或返回不相关条目；保底不保证绕过这些障碍。

`results` 的 `public_map_listing` 表示已经读取的地图商户条目，只支持其列示信息；不是已核实周边关系、当前营业和场所适用性。每条的 `source_urls` 对应实际读取的检索页；`searches` 仅保留查询状态、数量与覆盖，不重复返回商户正文。模型审阅全部本次候选，按地址区分校内 / 校外 / 其他学校内部 / 位置待确认，再判断需求匹配，不按搜索排名直接列“学校附近最好的”。有效空结果返回 `no_results`；失败 / 不可读返回 `search_unavailable_or_unreadable`；部分成功保留成功条目，`partial` 与 `failed_urls` 表明缺口。有结果但不相关也应如实说明没有已核实候选。

已有本轮实际发现的地图页但正文缺失，可仅补读这些页，避免重跑搜索：

```text
python -I -S -B -X utf8 "<技能目录>/scripts/nearby.py" --query "咖啡厅" --read-url "<本轮发现的https地图/place/详情地址或results中的map_link>"
```

最多4个 `--read-url`，仅允许公开地图 `/place/` 详情，或本轮结果给出的 `https://map.baidu.com/?qt=inf&uid=<真实UID>`。后者仅允许 `qt`、`uid` 两个单值参数，核对响应 UID 与请求一致，结构可读才返回已读取详情；错误对象、验证码、错店或403不会冒充成功。不能附加 Cookie、凭证参数或猜 UID。其他来源由环境网页工具读取。地图跳转链接 `map_search_link` 只供用户打开，标明“地图检索入口”，不声称已经访问，不当作店铺证据或完整导航。

`--read-url` 模式仅补读，不重新检索。平台检索结果已含名称地址时无需为“补正文”重复请求；字段不足时再补读真实发现的详情。`results[].map_link` 是由本次返回的商户 UID 生成的地图定位入口，`map_link_fetched: false`；同样不混进已读来源。脚本固定本校位置；用户明确在其他地点时，由环境搜索按其地点查，不用本校脚本冒充其他地点结果。

## 与其他模块衔接

“附近咖啡厅 / 校外聚餐”进入本模块；“A食堂吃什么”仍用校内匿名餐饮接口。“附近最便宜的咖啡”仅比较本次核实店铺的可比商品与规格，不触发校园食堂全量遍历，也不声称全区域最低价。“下课后去哪喝咖啡”若已给课表，可结合确认的下课时间；没有路线 / 营业证据不保证来回赶得上。

用户让查询打印、修手机等店铺，只提供有依据的店铺信息，不推断学校官方合作。路线问题可给真实来源或地图入口；尚无校内路线数据库，不能编校门出入口、开放时间或捷径。用户只想找地方，不自动扩展天气、预订、下单、支付、收藏或跨会话偏好记录。

## 收尾与状态

已接入的是“固定校址的公开实时检索、可读详情核实、模型筛选及地图入口”；未接入实时 POI 数据库、精确导航、排队和预约，不仅写角色介绍就宣称这些能力已经实现。

保持统一收尾：先列**本次获取的 URL**，环境真实记录与脚本 `retrieved_urls` 合并去重；`failed_urls` 单列说明。搜索页已读取但条目页面未读时，不能把条目 URL 列为已获取；正文可以列其为“待读取的线索”。生成的地图入口单列，不混进证据清单。最后给“快速预览：” Markdown 表格：

| 店铺 / 服务 | 地址与位置依据 | 适合需求 | 价格 / 营业信息 | 待核实项 |
|---|---|---|---|---|

无结果时仍给一行真实状态。没有联网成功不能用旧店铺记忆、演示数据或参考项目的样例代替真实查询。
