# 实时可溯源证书咨询

处理“我这个专业要考什么证”“哪些是必须的”“四级和专业证先考哪个”“这个证现在能报吗”“预算有限该选哪一个”等自然表达。结合 [培养方案](curriculum.md)、用户明确目标和当期官方信息给可执行建议，不把咨询变成证书大全。报名咨询接续 [考试信息](exam-info.md)，备考接续 [学习计划](study-plan.md) 和 [错题教练](exam-coach.md)；保留同轮目标和时间预算。

## 对话与证据

先用上下文中的入学年级、层次、专业 / 班型、目标、已持证和预算。不要要求成绩单；缺成绩只使相应资格待确认。只问会改变结论的缺口一次，其余先做能完成的查证。用户只问一种证书，直接查该证书，不强制先下载培养方案；问“我们专业必须考什么”则必须先读适用专业的毕业要求。

每项结论都属于以下一种，保留原文语气：

| 类型 | 足够依据 | 不可推断 |
|---|---|---|
| 毕业明确要求 | 适用培养方案毕业条款或适用校方补充规定 | 职业面向的证书“举例”不能替代 |
| 方案列举 / 推荐 | 方案对应栏目及原文措辞 | 不把清单全变成必考，不把“或”变成“且” |
| 岗位法定准入要求 | 适用职业和地区的主管部门现行规定 | 不把企业认证当国家职业资格 |
| 发展建议 | 用户目标、相关课程和已核实证书内容 | 明确是模型建议，不称校方要求或保证就业 |

“必须获得任一证书”和“必须获得某个证书”不同；保留等级、替代范围、期限和例外。“证书类课程”“3+证书”入学要求、HTTPS证书等技术内容，不自动归为学生应考证书。原文冲突、模板性制订说明、图中无法核实的条款单列，不擅自裁决。

## 实时搜索与官方核实

每次涉及证书现状、在售考试、资格、费用、考试版本 / 代码、报名日期、有效期、停考替代或“含金量”的咨询，使用本轮可用的环境搜索和网页工具。搜索由模型按本次问题构造，如“证书全名 + 主办单位 + 当前年份 + 报考条件 / 广东 / 官方通知”，不是固定口令。先检索识别官方主办方，再读对应正文；搜索结果只能用来发现链接。

建议选2至4个与目标直接相关的候选，用户指定更多再展开。独立来源可4路并发，依赖关系保持先后，不先抓所有证书。优先级：

1. 适用学校培养方案和校内报名公告：判断毕业要求、校内窗口和校内名额。
2. 考试主办方 / 主管部门当前公告、大纲和证书规则：判断资格、内容、获证条件、版本与有效期。
3. 省级承办机构 / 考点通知：核实地区报名时间、考点和费用。全国考试日不能推算本校报名日。
4. 企业认证使用发行企业正式认证站点；招聘、培训宣传或个人帖子仅作另外注明的参考，不用于证明校方必考、官方资格或就业收益。

本校教务事项从主站通知公告 `https://www.suit-sz.edu.cn/index/tzgg.htm` 查找公开线索，核实正文的相关性、适用对象与考次；不接入教务内网，不把历史公告当成当前报名规则。直接读取受阻时可用 `official_fetch.py --exam school`，或按 [新闻模块](news.md) 用 `news.py --category academic --days 30 --limit 40` 读取主站公告供模型筛选；公开未检出不代表校内未发布，30天窗口未检出也不代表从未发布，可根据明确考次调整日期范围。

已内置的官方入口及域名见 [official-sources.json](official-sources.json)。CET 首选考试动态栏目；NCRE 与软考是不同考试，不互换科目、等级和报考条件。通用入口不是具体规则依据，必须继续读适用公告。其他证书用环境搜索定位真实官方站点；无法识别发行方时先说明身份未核实，不推荐付费报名。

按已读取证据核对：证书全名 / 级别、发行方、资格条件、考试与获证的区别、学段年级限制、考次与地区、报名起止、费用口径、考试内容 / 代码、有效期 / 续证、官方报名入口。只呈现用户所需项；信息不足留未知，不填常识猜测。没有任何当前适用公告就写“当前考次尚未核实”，往年时间只能另列为历史参考。使用具体日期，区分发布时间、报名日、考试日；不得把已过期窗口写成仍可报名。

“值不值得考”围绕目标匹配、已有课程基础、时间、公开费用及续证负担解释取舍。不虚构通过率、薪资涨幅、企业普遍认可度或排名；有证据也说明样本范围。若主要目标是毕业，先解决明确硬要求；学习基础不足时先给准备任务，不直接建议报昂贵高阶认证。

## 内置 Python 最后保底

环境缺少搜索 / FETCH 或官方页面读取受阻时，自动使用包内预设脚本获取已配置官方入口及真实发现的正文，不让用户自己运行、不临时写爬虫。调用方法：

```text
python -I -S -X utf8 "<技能目录>/scripts/official_fetch.py" --exam cet
python -I -S -X utf8 "<技能目录>/scripts/official_fetch.py" --exam ncre
python -I -S -X utf8 "<技能目录>/scripts/official_fetch.py" --exam ruankao
python -I -S -X utf8 "<技能目录>/scripts/official_fetch.py" --exam ntce
python -I -S -X utf8 "<技能目录>/scripts/official_fetch.py" --exam accounting
python -I -S -X utf8 "<技能目录>/scripts/official_fetch.py" --exam school
python -I -S -X utf8 "<技能目录>/scripts/official_fetch.py" --exam ncre --url "<本次已发现且域名在登记范围内的官方正文URL>"
```

`--exam` 按真实证书选择，企业认证可选 `aws`、`huawei`、`huawei-cloud`、`tencent-cloud`。脚本是公开官方页面读取器，**不是通用搜索引擎**；不能因入口可访问就声称已完成全网搜索或取得JS渲染的规则。其链接只是发现，必须读取正文才能引用。

单请求默认超时 20 秒，可用 `--timeout 30` 调整为 5 至 60 秒；临时失败仍最多三次尝试。超时与资格未通过是两种不同结论。

未知发行方、配置域名外正文、脚本返回空壳、PDF或图片不可读时，保留已获取证据并说明尚未验证项。没有通用搜索能力时如实写“已查询内置官方来源，未完成全网检索”，不能用模型记忆补造成实时事实。培养方案取数受阻则用 `curriculum.py`，只加载目标专业；缺少工具、两种方法都失败时交付条件分析和真实缺口，不无限重试。公开读取的401 / 403、登录页或平台拒绝不绕过。

## 输出与后续承接

先直接回答“必须哪些 / 建议先考哪个 / 当前是否具备已知条件”，再解释理由与待核实项。资格用“符合已列条件 / 不符合已列条件 / 信息不足”，不承诺报名或获证成功。每条关键事实紧邻标注“文件及条款 / 官方正文链接 + 发布或核验日期”；建议与事实分开。已有用户成绩只作用户提供数据，不联网查个人账号。

比较可用“证书与级别 / 与专业或目标关系 / 是否硬要求 / 当前资格与时间 / 成本及限制 / 依据”。给完建议可直接承接用户要求的学习计划或练习；不强行加自测，不另问是否需要查官网。

收尾仍按根入口先列“本次获取的 URL”：合并本轮搜索和正文实际读取地址，发现未读的链接单列；失败另列。每项官方结论必须能对应已读正文，不能只给官网首页。最后为“快速预览：” Markdown 表格，保留“要求性质、推荐顺序或资格状态、下一步、依据 / 待核实项”。没有实际联网写“本次未获取网络 URL”，不得使用“已实时核实”。
