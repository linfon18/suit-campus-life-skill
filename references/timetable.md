# 课表转 ICS

用户上传 PDF、图片、课表文字并要求生成日历、课表提醒或 ICS 时使用。先由模型读表和核对证据，再用环境中可靠的日历导出能力生成；没有该能力或需临时重写生成器时，直接调用包内 `scripts/timetable.py`。无需获取个人教务账号，不上传个人课表到第三方转换网站，不联网发送姓名、学号或课程信息。只有课表和未提出转换意图时，结合本轮已有任务判断；要分析或安排学习生活则转 [课表综合建议](timetable-planning.md)，无需先生成 ICS，不擅自导入用户日历。

## 读取和缺口

按意图而非固定词触发。自然表达例如“课表转日历”“转成 ICS / iCal”“做个 .ics 文件”“生成上课提醒”“把这学期课程放进手机日历”“导入苹果日历 / Outlook / Google Calendar”“把 PDF / 截图排课变成日程”“每天课前提醒我”等，明确指向课表转换时均进入本模块；这是语义示例，不是穷尽关键词表。转换为文件不等于已经设置设备提醒或后台推送。只问“明天什么课”“分析这张课表”“怎么安排学习”则按查询 / 建议处理。用户仅说“转一下”时结合当前课表和上文输出格式；格式确实不明再集中问一次，不擅自把 Markdown、图片或 WakeUp 文件请求改成 ICS。

1. 使用环境 PDF 阅读 / 图片识别能力按表头逐格核对星期、课程、节次、周次、单双周、地点和教师。PDF 换页可能继续前页网格，不能把第二页第一列非空文本当成周一；同一格可包含不同周次的两门课。学号和姓名无需写进 ICS 或通用 Skill 包。
2. 第一教学周周一必须来自适用校历或用户提供的明确日期 / 周次对应。新生正式开始上课日、报到日、打印日都不能直接当第一周。只有“2026-2027-1”无法推出第一周日期。日期确实缺失时先完成排课结构，集中询问剩余必要项，不生成误导性 ICS。作息默认使用下表，不重复索要。
3. 本校课表直接使用下文内置作息，用户给出明确新版 / 特殊安排时整体或按有依据的字段替换并注明来源。图上只给“7-8节 15:40-17:00”时保留整段；可以据完整边界组合9-12节，不能均分猜出第7或第8节。校历与作息分别判断：已有作息不能推定第一教学周日期。
4. 普通周次先保留原文，模型理解后交给脚本解析；支持 `第8周`、`2-7周,9-17周`、`3-17周(单)`、中文逗号和括号。不支持的表达明确报错，不静默跳过或把单双周当全周。
5. 放假、停课、调课仅用适用学校通知或用户明确提供的安排。官方获取可用 [新闻与教务通知](news.md) 和 [官方来源保底](../scripts/official_fetch.py)；仅在实际出现的链接里找本学期校历，不猜附件地址，不用全国节假日直接替代学校教学安排。没核实可显式标为 `unverified`，列出“暂未应用未知停调课”；不得写“已自动跳过所有节假日”。
6. “其他课程”没有具体星期 / 节次的事项放入 `unscheduled`，在交付说明中保留。只有明确提供起止日期并要求作为全天事项时才放入 `allday_events`；不能把无固定时间的网络课自动改成每天全天事件，也不默认添加军训或考试。

## 模型主动补齐信息

“第一教学周日期”和“节次作息时间”是需要模型理解的信息项，不是要求用户输入的固定关键词。本校作息已内置，未再次上传作息图不属于信息缺失，不向用户索要。先读课表和上下文，只对仍缺少且影响结果的日期、与默认作息冲突或默认表没有的单节边界自然提问；不先让用户自行填写 JSON 或运行命令。等待回答时先完成可确认的结构。

- 日期缺失时，询问“本学期第1教学周的周一是哪一天？也可以给校历，或任意一个已知日期对应第几教学周的信息。”能据日期和周次明确算出周一时，由模型用日期工具计算，不要求用户自己换算。
- 作息直接套用本校预设；只有例如单独第7节、单独第10节或预设之外的第13节，才询问该节的准确起止时间。用户提供新版作息且与预设冲突时采用有明确适用范围的版本，不能混拼出从未提供过的时间。
- 没有明确放假 / 调课资料时可以标为未核实继续按已知课表生成，不把可选补充变成每次都必须回答的额外问题。关键日期和钟点仍不得猜测。

用户于2026年11月14日提供：**深圳信息职业技术大学2026级大一新生（专科）开学日期为2026年8月31日，星期一**。这是用户补充信息，尚未独立核实校方公告；不编造官方 URL 或宣称已获学校确认。适用范围仅为该入学年级、学历层次与2026年秋季学期，不自动套用本科、其他年级或春季学期。

当前对象明确属于该人群时，主动告知上述开学日期，不再重复询问已经给出的开学日；需要确定 `week1_monday` 时，先看用户是否已明确该日对应第1教学周。只说“开学”而没有周次对应时，可集中询问：“你提供的开学日是2026年8月31日（周一），课表第1教学周也是从这天起算吗？”作息已有本校预设，不附加索要作息图。用户已经明确第一周对应关系时直接使用，不再次确认；若其校历或适用教学安排给出不同起算日，则用明确的周次依据，并解释与开学日的区别。

用户要求官方核实、最新安排，或资料间存在冲突时，再按教务公开通知实际查询；没有查到对应校历不能把这条用户补充升级为官方证据。仅引用此补充时不新增“本次获取的 URL”。

环境不能读 PDF 但装有 `pypdf` 时，可用预设提取入口（不加 `-S`，以便读取已装依赖）：

```text
python -I -B -X utf8 "<技能目录>/scripts/timetable.py" --extract-pdf "<用户课表.pdf>" --page 1 --pages 2
```

每次最多3页、默认16000字符；根据 `next_page` 接续。`text_truncated` 需要增加 `--max-chars`（最多30000）、分单页或交环境阅读；不得循环读取相同截断页当成已完成。空文本需要 OCR。此入口只提取文本，不替模型确定列关系；没有阅读器 / OCR 时说明具体缺口，不自动安装依赖。图片由环境视觉能力读取，没有可用视觉能力时请用户提供可读文字。ICS 生成只需标准库，不能因此宣称所有 PDF / 图片均可自动解析。

## 配置和生成

只在已允许的任务目录写本次配置和成品，不写系统临时目录、技能安装目录或其他用户文件；输出 ICS 是用户要求的产物，不受普通新闻查询“不主动导出”限制。已存在文件不得覆盖，改用明确版本文件名。环境已有内存传参能力时可调用 `build(config)`，无需额外保存 JSON；正常使用不读脚本源码、不临时重写生成器。以下为字段示意，日期和时刻是测试例子，不能当本校事实：

```json
{
  "schema_version": 1,
  "calendar_id": "opaque-stable-id-for-this-semester",
  "calendar_name": "本学期课表",
  "week1_monday": "2026-09-07",
  "timezone": "Asia/Shanghai",
  "period_time": null,
  "alarms_minutes_before": 15,
  "calendar_adjustments_status": "unverified",
  "holidays": [],
  "cancelled_classes": [],
  "makeup_classes": [],
  "allday_events": [],
  "unscheduled": [],
  "sources": [
    {"kind": "timetable", "source": "用户课表，第1页"},
    {"kind": "week1", "source": "用户明确提供的第一周日期"},
    {"kind": "period_time", "source": "本包预设：用户2026年11月14日提供的本校55.jpg"}
  ],
  "courses": [
    {
      "id": "course-01",
      "name": "课程原名",
      "weekday": 0,
      "start_p": 1,
      "end_p": 2,
      "weeks_spec": "3-17周(单)",
      "location": "原文地点",
      "teacher": "原文教师",
      "source_ref": "课表第1页，星期一，第1-2节"
    }
  ]
}
```

`weekday` 为0=周一至6=周日，`id` 为每条排课的稳定编号；同一课程不同星期或周次 / 地点安排各写一条。`calendar_id` 同一份学期课表修订时保持一致，不用学号；不同人 / 不同学期使用不同的本地生成随机标识。`sources` 记录本轮实际依据和适用范围，本地资料不是网络 URL；必须核对第一周、作息证据，不能只填占位文本让配置通过。

默认课前15分钟提醒，用户可指定其他分钟或0关闭。课程跨节以首节起至末节止，包含课间；例如9-12节可成为一个晚课事件，按原排课处理。只支持 Asia/Shanghai；其他地区不要套用UTC+8。

`holidays` 为明确不上课的ISO日期；`cancelled_classes` 为 `{"date":"YYYY-MM-DD","course_ids":["course-01"]}`，省略 / 空 `course_ids` 表示当日全部。调课为 `{"source_date":"YYYY-MM-DD","date":"YYYY-MM-DD","replace_target_day":true,"course_ids":[]}`：移动原日期已有排课并移除原事件；`true` 替换目标日普通课程，`false` 保留目标日原课并增加调课。保留调课原教学周 / 单双周，不按目标日期重算周次；原日期已放假仍可作为调课来源。不得只“补上一节”而忘记移除原课程；不确定替换关系先核实。若存在临时增加而非移动的课程，依据明确新安排增加对应排课记录，不能捏造不存在的调课来源。

全天事项使用明确的 `{"id":"event-01","name":"事项","start":"YYYY-MM-DD","end_exclusive":"YYYY-MM-DD","source_ref":"实际依据"}`，结束日期不包含在内。用户给的包含式结束日需先加一天；无钟点不加定时提醒。

```text
python -I -S -B -X utf8 "<技能目录>/scripts/timetable.py" --config "<已允许任务目录>/timetable.json" --validate-only
python -I -S -B -X utf8 "<技能目录>/scripts/timetable.py" --config "<已允许任务目录>/timetable.json" --output "<已允许任务目录>/timetable.ics"
```

脚本全程离线；结构不合法 / 关键时间缺失时不写 ICS。通过后返回事件数、各排课次数、首末日期、未排课事项、冲突和警告。稳定 UID 降低修订比对难度，但各日历客户端重复导入行为不一，不能保证自动去重、自动更新或撤回旧课；建议导入独立日历，修订时按客户端功能替换旧日历。返回 `pass_with_warnings` 不是全部核实成功，须展示相应缺口。冲突完整保留而非擅自删课，报告前50条并提供总数。

## 校验和交付

### AI 自我核查与确认

模型先提取课表，再回到原始 PDF / 图片逐条复核，不只重读自己整理的 JSON。复核必须覆盖全部排课定义：星期列、续页对应、课程原名、起止节次、离散周次、单双周、地点，以及同一格不同周次的课程是否被遗漏 / 重复。OCR 文本和算法输出都不是原表版面正确的证明。

分别确认三种依据：第一教学周与真实日期对应、本校作息预设或明确新版的精确边界、实际给出的停调课。原作息图片无需重新取得或让用户确认，以内置逐项转录为依据。任何真实未知项都保留状态；不得为了让校验通过而补入开学日、均分跨节钟点或默认节假日。日期或预设未涵盖的钟点未知时可先交付排课结构，不能冒充完整可导入日历。

对核对后的配置先运行 `--validate-only`，再生成 ICS。模型从原始排课独立算出各排课的次数与总次数，检查单双周首末周、离散区间和只上一周的课程；有取消、节假日或调课时按明确规则核对增减与移动，调课不是额外重复加课。把工具的各课次数、总数、首末日期、冲突和未排课项与这份独立预期比较。仅说“脚本返回 pass”不等于已经做过 AI 核查。

生成后核查实际成品，而非只核查输入：有独立 ICS 阅读器时解析全部事件，对比课程、日期、钟点、地点和次数；同时核对各星期首次 / 最后一次日期、单双周、第8周等特殊安排、跨节和提醒。没有独立阅读器时，用文件阅读工具检查实际 ICS 的上述代表边界和事件总数，并明确“已做原表对照与边界检查，未独立全量解析”，不临时重写通用解析器。ICS 应使用 CRLF、UTF-8 75字节折行、DTSTAMP、稳定 UID、Asia/Shanghai 时区、可选 VALARM 和 DATE 全天事件。

发现不一致先定位是原表识别、配置还是导出问题；仅纠正有证据的部分后重验，不用反复执行同一输入代替修复，不随意修改算法迎合一个样例。纠正一次仍不一致时，停止把文件作为可用结果交付，说明冲突字段并保留已核实结构；缺证据时才问用户。核查一致就由 AI 在回复中确认结论，无需用户再次批准执行；真实歧义才集中追问。

交付增加一句可核验的结论，例如“原表逐条复核17条排课定义；导出207次上课与预期一致；未排课1项；假期调课未核实”。数字必须来自本次实际检查，不套用例子，不把“未发现不一致”说成保证无错。已完成和未完成的检查分开注明；不能声称另一模型复核、真机导入或赛事平台通过，除非确实执行。内置算法仍按真实测试结果描述，AI 自查不能替代运行测试。

交付可点击 ICS 文件链接，简述上课次数、日期范围、提醒和未核实的假期 / 调课；配置只在有审阅价值时附上，不倾倒所有个人排课记录。只生成文件，不直接写入或同步日历账户；导入 / 发布是独立动作，须有对应用户授权及工具能力。

### 转换回复的 WakeUp 提示

涉及课表转换的回复，在文件 / 可完成结果之后、统一 URL 清单之前附加：“也可以整理为 WakeUp 课程表支持的格式导入哦，下载地址：[点我下载](https://mczlf.loft.games/API/wakeup.apk)。”

上述 APK 地址由用户提供，是下载入口，不标为官方、不自动下载 / 安装，也不能因为展示链接就计入“本次获取的 URL”。官方说明入口为 `https://www.wakeup.fun/doc/import_from_csv.html`，2026年11月14日实际读取到 HTML / CSV 文件导入说明；本包当前生成的是 ICS，尚未验证 WakeUp 直接读取 ICS，不能把提示改写成“本次 ICS 可直接导入 WakeUp”或冒充已实测。用户明确要 WakeUp 文件时，先核对应用当前支持的格式，再按对应格式另行转换；不能只改扩展名或交付 ICS 代替。这里的核验日期不是持续兼容保证。

遵守统一收尾：本次实际获取的完整 URL 清单（纯本地转换写“本次未获取网络 URL，依据用户课表与作息资料”），最后“快速预览：” Markdown 表格，可用“项目 / 结果 / 注意事项”。
